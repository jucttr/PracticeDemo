# 数组去重方式总结

对应源码：`index.js`（正序 9 个例子 + 末尾 2 个反面例子）。

按**去重思路**归类，正序是 5 类：

| 类别 | 代表实现 | 关键点 / 局限 |
| ---- | -------- | ------------- |
| 1. Set（ES6） | `unique`、`[...new Set]`、`likeSet`（手写） | 最简洁，能处理 `NaN`；对象按引用区分，内容相同也去不掉。手写版还原 SameValueZero，语义一致但 O(n²) |
| 2. 遍历 + 结果集查找 | `unique2`(indexOf)、`unique5`(includes)、`unique8`(reduce+includes) | 同一套路，只是查找 API 不同：`indexOf` 用严格相等，去不掉 `NaN`；`includes` 可以 |
| 3. 双重循环 + splice | `unique3` | ES5 最常用，原地删除；用了 `==`，会误删 `null`，`NaN` 也去不掉 |
| 4. filter + 首次索引 | `unique7` | 只保留「元素第一次出现的位置 == 当前索引」的项，`NaN` 去不掉 |
| 5. Map 哈希（正确写法） | `removeDuplicate` | Map 键用 SameValueZero，不转字符串、不合并对象，O(n)；和 Set 行为一致 |

> [!warning] 反面例子：普通对象做哈希（`unique4` / `unique6`）
> 代码末尾单列，仅作反面教材。属性名会被转成字符串：`1` 和 `'1'` 被合并，所有对象变成 `[object Object]` 被误合并。`unique6` 用 `typeof + item` 拼 key 区分了类型，但对象依旧全被合并、key 可能冲突。**同样是哈希思路，正确做法见第 5 类 Map 版。**

> [!tip] 三个必记坑点
>
> - **NaN**：`===` / `indexOf` 去不掉，`Set` / `includes` / `Map` 能处理
> - **对象引用**：内容相同也不会被认为是重复
> - **类型混淆**：普通对象属性法会把 `1` 和 `'1'` 当成同一个 key，Map 不会

## 面试口述版

> [!note] 可直接回答面试官
> 这份代码按思路可以归成 5 类：
> 
> 第一类是 ES6 的 `Set`，最简洁也最推荐，手写版就是还原它的 SameValueZero 规则；
> 
> 第二类是遍历数组、在结果集里查找，`indexOf`、`includes`、`reduce` 都是同一思路的不同写法；
> 
> 第三类是 ES5 常用的双重循环加 `splice` 原地删除；
> 
> 第四类是 `filter` 配合 `indexOf`，只保留首次出现的位置；
> 
> 第五类是用 `Map` 做哈希，键不转字符串，是普通对象哈希的正确替代。
>
> 要注意几个坑：
> 1、`NaN` 用 `indexOf` 或 `===` 去不掉，但 `Set`、`includes`、`Map` 可以；对象因为引用地址不同不会被当成重复；
> 2、普通对象做哈希还会把 `1` 和 `'1'` 合并、把所有对象合成一个 key，所以哈希要用 `Map` 而不是普通对象。

## 延伸追问：真正的去重要考虑什么

> [!important] 先点破本质
> 去重的难点不在「怎么遍历」，而在「怎么定义两个元素相等」。前面那些局限——`NaN` 去不掉、`1` 与 `'1'` 混淆、对象内容相同却去不掉——根源都在这一条。

| 因素 | 要问自己的问题 | 默认选择 |
| ---- | -------------- | -------- |
| 相等语义 | 用 `==`、`===` 还是 SameValueZero？`==` 有隐式转换，`===` 去不掉 `NaN` | Set / includes / Map 用的 SameValueZero |
| 特殊值 | `NaN`、`+0/-0`、`undefined`、`null` 算不算重复？ | SameValueZero 最省心；区分 ±0 才用 `Object.is` |
| 引用类型 | 对象按地址比还是按内容比？ | 按业务唯一键（如 `id`）最可靠，`JSON.stringify` 有冲突和循环引用坑 |
| 顺序与副作用 | 是否保序（留首次出现）？是否原地修改？ | 保序 + 返回新数组 |
| 性能与规模 | 数据量多大？ | 双循环 O(n²) vs 哈希 O(n)，空间换时间 |

> [!note] 口述版
> 核心不是遍历，而是先定义清楚「什么算相等」：相等语义、`NaN`/`±0` 等特殊值、对象按地址还是内容、是否保序和原地修改、性能。默认用 `[...new Set(arr)]`，对象数组按业务 key 配合 `Map`。

## 手写 Set：实现类似 `[...new Set(arr)]` 的函数

关键是把 Set 内部的 **SameValueZero** 规则还原出来：`NaN` 等于自身，`+0` 与 `-0` 视为相等，其余按 `===`。

```js
function likeSet(arr) {
    const res = [];
    for (const item of arr) {
        // SameValueZero：=== 负责常规值与 ±0 合并，双否定负责 NaN
        if (!res.some((x) => x === item || (x !== x && item !== item))) {
            res.push(item);
        }
    }
    return res;
}
```

- `x === item` 覆盖常规值，也顺带把 `+0` / `-0` 合并（`===` 认为二者相等；只有 `Object.is` 才区分）。
- `x !== x && item !== item` 专门抓 `NaN`——它是唯一一个不等于自身的值。
- 边遍历边 push，天然保留**首次出现的顺序**。
- 实测：`NaN`、`+0/-0`、类型区分、不相邻重复、对象引用五种情况，输出与原生 `Set` 一致。
- 取舍：这里用 `some` 是 O(n²)；原生 Set 靠哈希做到 O(n)。语义相同，性能不同。

> [!tip] 口述版
> 手写就还原 SameValueZero：用 `===` 判常规值，再补一句 `NaN !== NaN` 的特判，因为 NaN 是唯一不等于自身的值。边遍历边存，天然保序。这样语义和 Set 一致，区别只是 Set 用哈希做到 O(n)，手写版查找是 O(n²)。

## 面试官问「有几种」，挑哪 3 个讲

> [!important] 先给框架，再挑三个
> 别一上来答「3 种」——那听起来像背的。正确节奏：1、先说「按思路大概 5 类」；2、再讲「我挑 3 个代表性的展开」；3、三选是**展开的深度**，不是**答案的全貌**。

挑 **Set、Map、双循环 splice**，三个各承担不同的交流功能：

| 挑它           | 讲什么                            | 抛给面试官的钩子                                             |
| ------------ | ------------------------------ | ---------------------------------------------------- |
| Set（展开写法）    | 现实首选，`[...new Set(arr)]` 一句给答案 | 相等语义是 SameValueZero，NaN 能去、对象按引用                     |
| Map 哈希       | 键不转字符串、O(n)、行为和 Set 一致         | 同理的普通对象哈希我踩过坑——`1` 和 `'1'` 合并、对象全变 `[object Object]` |
| 双循环 + splice | 唯一能现场手撕的底层写法                   | 源码用了 `==` 会误删 null，得改成 `===`，代价 O(n²)                |

关键在第二行：**Map 是唯一能自然带出反面例子的入口**。底部那两段哈希代码主动讲是挖坑；等面试官问「踩过什么坑」再拿 Map 做对照说出来，就从「背方法」变成「有实战判断」。

> [!note] 条件分支
> 若面试官强调「兼容老环境、不用 ES6」，把 Map 换成 `indexOf`——它去不掉 NaN、换成 `includes` 就行，同样是个边界交流点。

> [!tip] 口述版
> 按实现思路分大概五类：Set、遍历加结果集查找、双重循环、filter 加索引、还有哈希。我挑三个代表性的说一下。
>
> 第一是 Set，现实里直接用 `[...new Set(arr)]`，它按 SameValueZero 比较，所以 NaN 能去重、对象按引用区分。
>
> 第二是哈希，但我想说的是普通对象不能这么用——属性名会被转成字符串，`1` 和 `'1'` 会合并，所有对象都变成 `[object Object]`；正确做法是用 `Map`，键是 SameValueZero，不会转字符串，也是 O(n)。
>
> 第三是双重循环加 splice，ES5 时代最常规的写法，能现场手写，但要注意用 `===` 而不是 `==`，否则 null 会被误删，而且复杂度是 O(n²)。
>
> 另外两个——`indexOf` / `includes` 那一族和 `filter` 加首次索引——思路和前面有重叠，就不展开了。
